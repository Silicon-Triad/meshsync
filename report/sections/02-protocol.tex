\section{Protocol specification (R1)}
\label{sec:protocol}

This is our complete wire protocol in short form; \code{docs/PROTOCOL.md} in the repository adds
worked examples. Integers are unsigned and big-endian. JSON is UTF-8. A \code{peer\_id} is 8
uppercase hex characters; all other hex values are lowercase. \code{K} is the group's 32-byte
shared secret. It never crosses the wire.

\subsection{Overview}
\label{sec:proto-overview}

All peers are equal; there is no server. On each TCP connection, the side that dials is the
\emph{initiator} (I) and the other is the \emph{responder} (R). Only the peer with the lower
\code{peer\_id} dials, so each pair has one connection. Discovery uses UDP broadcast on port 47000;
everything else uses TCP port 47001, optionally inside TLS~1.3. A closed connection is redialled
every 5\,s while the peer is still known.

\subsection{Discovery datagram (UDP)}
\label{sec:proto-discovery}

Each datagram is one JSON object of at most 512 bytes with exactly nine fields: \code{magic}
(\code{"MS"}), \code{ver} (1), \code{type} (\code{"ANNOUNCE"} or \code{"LEAVE"}), \code{peer\_id},
\code{name}, \code{tcp\_port}, \code{index\_rev}, \code{ts} (Unix seconds) and \code{tag}. The tag is
the HMAC-SHA256 under \code{K} of the other eight fields, written as canonical JSON (keys sorted,
no spaces). A receiver drops the datagram silently at the first failed check: (1)~size, JSON and
fields valid; (2)~not its own \code{peer\_id}; (3)~tag correct; (4)~\code{ts} within 30\,s of its
clock; (5)~\code{ts} newer than the last one from that peer. It then removes the peer (LEAVE) or
adds or updates it (ANNOUNCE). The peer's address is the datagram's source IP. Peers announce every
5\,s and send LEAVE at shutdown; a peer silent for 15\,s is dropped.

\subsection{TCP framing}
\label{sec:proto-framing}

Every TCP message is a 12-byte header (Table~\ref{tab:header}) and a body. The reader takes
exactly 12 bytes, checks the fields in table order, then reads BODY\_LEN bytes. Every failed check
is fatal. A body must have exactly the keys listed for its type.

\textbf{REQ\_ID.} A request has a non-zero REQ\_ID, and its reply carries the same one, so replies
may come in any order. The initiator uses odd IDs and the responder even ones, so each side knows
which messages are replies. REQ\_ID 0 marks messages that are neither: the handshake, NOTIFY, BYE,
and an ERROR not tied to a request.

\subsection{Messages}
\label{sec:proto-messages}

Table~\ref{tab:msg-formats} lists every TCP message. Codes 0x01--0x04 are legal only during the
handshake, ERROR at any time, and the rest only after it. Nonces are 16 random bytes in hex. An
index entry has exactly \code{path}, \code{size}, \code{file\_hash}, \code{chunks} (the SHA-256 of
each chunk), \code{version} (\code{peer\_id} $\rightarrow$ counter) and \code{deleted}. A peer keeps
at most 8 CHUNK\_REQs outstanding per peer and sends PING every 10\,s.

\subsection{Legal message order}
\label{sec:proto-order}

Figure~\ref{fig:protocol} shows the order of messages on a new connection and the states it

INTERNAL and the link stays open; a reply that matches no request is ignored. If both peers dial
each other, both keep the link whose initiator has the lower \code{peer\_id}.

\subsection{Security}
\label{sec:proto-security}

\textbf{HMAC handshake.} Each side proves it knows \code{K} by signing the other side's fresh nonce:
$\mathit{mac\_r} = \mathrm{HMAC}(K, \mbox{\code{R}} \,\|\, \mathit{nonce\_i} \,\|\, \mathit{nonce\_r})$ and
$\mathit{mac\_i} = \mathrm{HMAC}(K, \mbox{\code{I}} \,\|\, \mathit{nonce\_r} \,\|\, \mathit{nonce\_i})$,
over the raw nonce bytes. The role letter stops a MAC being sent back as the other side's proof,
and fresh nonces stop replay. \textbf{TLS mode} (\code{--tls}) runs TLS~1.3 with certificates from a
group CA on both sides, before HELLO. After the handshake each side checks that the certificate's
name matches the peer's HELLO name. Plain mode exists only for the capture and as a baseline.
